102. Compare append and overwrite semantics for each layer.
| Layer         | Recommended mode                   | Why                                                |
| ------------- | ---------------------------------- | -------------------------------------------------- |
| **Landing**   | Temporary / move                   | Files are moved out after validation               |
| **Raw**       | **Append**                         | Historical accepted files must remain              |
| **Rejected**  | **Append**                         | Keep rejected files for audit                      |
| **Reference** | **Overwrite/replace when updated** | Static reference; new version replaces old version |
| **Processed** | **Append by date**                 | New daily partitions should be added               |
| **Analytics** | Depends on table                   | Curated summaries may be rebuilt or appended       |
| **Logs**      | **Append**                         | Never erase previous audit/run history             |

103. Define retention considerations for raw data and for logs.

-retain raw data for a relatively long period because it can be needed for:
Reprocessing with a new Spark logic
Debugging incorrect processed results
Auditing what was originally received
Recovering from downstream failures
Rebuilding processed/analytics data


-Log retention:
Keep logs long enough to troubleshoot and audit
pipeline executions.
Keep all logs for the lifetime of the project.
