96. Discuss why these files are processed as batch even though real network activity is continuous.
The network activity itself is continuous, but our training data arrives as daily CSV files containing hourly observations.
Therefore, batch processing is appropriate because Spark processes each file after it arrives.
We would consider streaming only if the source provided continuous events and the business required low-latency results.

97. Map batch to model training, and streaming to potential real-time scoring.
Model training is a batch workload because it uses accumulated historical data and does not require second-by-second processing. 
In a future production architecture, streaming could be used for real-time model scoring when live network events arrive and predictions are required within seconds or minutes. 
Our current dataset remains batch-based.

98. Present one decision where batch is the better engineering choice, and defend it.
I would choose batch for an executive dashboard refresh when the dashboard only needs to be updated every 30–60 minutes. 
Streaming would introduce Kafka, stream processing, monitoring and additional operational complexity without providing significant business value. 
Therefore, batch is the better engineering choice because it satisfies the latency requirement at lower cost and complexity.
